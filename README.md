# Pokédex API

A Rails + React application for browsing Pokémon. RESTful API backend with a React frontend using Ant Design — responsive card grid, type filtering, and detail pages with stats.

## Tech Stack

- **Backend**: Ruby on Rails 7.2 (on Ruby 3.4.5)
- **Frontend**: React 18, React Router 6, Ant Design 5
- **Database**: SQLite3 (development)
- **JS Bundling**: esbuild (via jsbundling-rails)
- **Testing**: RSpec + FactoryBot

## Prerequisites

- **Ruby**: 3.4.5 (see `.ruby-version` / `.tool-versions`)
- **Node.js**: 22+ (see `.tool-versions`)
- **Yarn**: 1.22+
- **SQLite3**

## Installation

```bash
bundle install
yarn install
bin/rails db:setup
```

`bin/rails db:setup` creates the SQLite database, runs migrations, and seeds it from PokeAPI. The seed step pulls all ~1025 Pokémon and downloads their official sprites into `public/pokemon/` — expect ~60-90 seconds and ~130MB on disk the first time.

To skip the seed or limit the data set:

```bash
bin/rails db:create db:migrate           # no seed
LIMIT=151 bin/rails db:setup             # only first 151 (Gen 1)
LIMIT=20 bin/rails pokedex:seed          # idempotent — adds/updates the first 20
```

## Running the App

```bash
bin/dev
```

`bin/dev` uses Foreman to run two processes together (defined in `Procfile.dev`):
- Rails server on port 3000
- esbuild in watch mode, rebuilding `app/assets/builds/application.{js,css}` on every change

The app is available at <http://localhost:3000>.

> If you don't have Foreman installed, `bin/dev` will install it on first run.

### Running them separately

```bash
# terminal 1
bin/rails s

# terminal 2
yarn build --watch
```

## Routes

The React frontend (rendered via React Router):

- `/` — paginated card grid of all Pokémon
- `/pokemon/:pokemonId` — detail page (image, types, description, height/weight, base stats)
- `/new` — create form

Hard-reloads of any of these work via an SPA-fallback route in `config/routes.rb`.

## API Endpoints

- `GET /api/v1/pokemon/index` — list all Pokémon (currently returns all 1025; pagination params not yet wired up)
- `GET /api/v1/pokemon/:id` — fetch a single Pokémon by its Pokédex number
- `POST /api/v1/pokemon/create` — create a Pokémon *(known bug: maps `params[:id]` to the AR primary key instead of `pokemon_id`, and does not persist `image_url`)*
- `DELETE /api/v1/pokemon/:id` — *(route exists; handler not yet implemented)*

See [docs/api_testing.md](docs/api_testing.md) for curl examples and [docs/plans/full-pokedex-buildout.md](docs/plans/full-pokedex-buildout.md) for the multi-phase build-out plan.

## Testing

```bash
bundle exec rspec
```

Suite currently covers the Pokémon model (validations, scopes, `base_stats` JSON serialization) and a basic request spec for the index endpoint.

## Build Notes

- esbuild compiles `app/javascript/application.js` into `app/assets/builds/application.js` and a sibling `application.css`. The build script lives in `package.json` and includes `--loader:.js=jsx` so JSX can live in `.js` files.
- The `application.css` is generated by esbuild from the `import 'antd/dist/reset.css'` in `app/javascript/components/app.jsx`. No Sprockets-side CSS compilation — Sprockets only digest-fingerprints the esbuild output.
- `app/assets/builds/` is gitignored; only `.keep` is tracked. Always run `yarn build` (or have `bin/dev` running) before booting Rails on a fresh clone.
